# M0 — foundations and engine gate

Goal: a build the user can install on Windows and on their Android phone that logs in
to the server, browses the media folders, and plays any file with frame stepping and
seeking, and that updates itself. It ends with a go/no-go on the playback engine,
measured on the real phone.

Not in M0: the library model (series, broadcasts), chat, sync, watch tracking,
downloads, the web player. Do not start them.

## Parts

| Part | Contents |
|---|---|
| A. Server skeleton | Config, SQLite, login with device tokens, folder scan with ffprobe, the API below, authorized range serving, Dockerfile, tests, CI |
| B. Client skeleton | Flutter app for Windows and Android: login, folder browser, player on `PlayerEngine`/`MpvEngine` (media_kit) with the M0 hotkeys, CI builds |
| C. Releases and updates | Nightly and stable channels on GitHub Releases, Velopack on Windows, APK self-update on Android, server image on GHCR |
| D. Engine gate | The benchmark in `tools/engine-bench` repeated inside the app on the real phone and on Windows; decision recorded in ARCHITECTURE.md |

A and B run in parallel against the API below. C follows A and B. D follows C.

## API for M0

JSON over HTTP under `/api`. Every route except login, refresh and `GET /api/server`
needs `Authorization: Bearer <access token>`. Errors are
`{ "error": { "code": string, "message": string } }` with a fitting status.

| Route | Request | Response |
|---|---|---|
| `GET /api/server` | — | `{ name, version, apiVersion }` |
| `POST /api/auth/login` | `{ username, password, deviceName, platform }` | `{ accessToken, expiresInSeconds, refreshToken, deviceId }` |
| `POST /api/auth/refresh` | `{ refreshToken }` | same as login; the refresh token rotates |
| `POST /api/auth/logout` | — | `204`; revokes this device |
| `GET /api/roots` | — | `{ roots: [{ id, name, kind }] }`, kind is `anime`, `stream`, `movie` or `tv` |
| `GET /api/roots/{rootId}/entries?path=` | relative folder path, default the root | `{ path, entries: [{ name, type: "folder" }, { name, type: "file", fileId, sizeBytes, durationMs? }] }`, folders first, natural sort |
| `GET /api/files/{fileId}` | — | `{ fileId, name, sizeBytes, durationMs, container, video, audioTracks, subtitleTracks, chapters }` from ffprobe |
| `GET /api/files/{fileId}/content` | `Range` supported | the file's bytes, `Accept-Ranges: bytes` |

Details:
- One account. Its username and argon2id password hash come from configuration; a CLI
  command prints a hash for a password. Login is rate-limited.
- Access tokens are short-lived (15 minutes); refresh tokens are per device, stored
  hashed, and revocable.
- `fileId` is stable for a path within a root and does not reveal the path.
- Paths from clients are resolved inside the root; anything that escapes it, including
  through symlinks, is refused.
- Only media extensions are listed (`mkv`, `mp4`, `ts`, `webm`, `mov`, `avi`, `m4v`);
  zero-byte files are hidden.
- Probing is lazy and cached by path, size and modification time. Listing a folder must
  not probe every file in it.
- Roots are opened read-only by the server in M0.
- Roots may contain symlinks that resolve inside the root; they behave like the files
  and folders they point to.
- File bytes are served by the server process in M0, and M0 runs one container
  (`api`); the nginx hand-off and the other containers come later.

Shapes the client relies on (`contracts/openapi.json` is generated from the same
schemas):
- `GET /api/server`: `apiVersion` is the number `1`.
- Tokens: the access token lasts 15 minutes (`expiresInSeconds: 900`). The refresh
  token expires after 30 days without use, and each refresh extends it. For 60 s
  after a refresh the previous refresh token still works and returns the same new
  one, so retrying a lost refresh response is safe.
- Listing: `path` is echoed normalised (no leading `./`, no trailing slash, `""` for
  the root). Names starting with `.` are hidden. File `durationMs` is present only
  when a cached probe exists.
- File metadata: `durationMs` is an integer or `null` when unknown. `container` is
  ffprobe's raw format name (e.g. `matroska,webm`). Every track `index` is ffprobe's
  global stream index. Fields marked `?` below are `null` when absent.
  - `video`: `null` or `{ index, codec, width?, height?, pixelFormat?, frameRate? }`;
    `frameRate` is a fraction string such as `"24000/1001"`; cover art is never
    chosen.
  - `audioTracks[]`: `{ index, codec, language?, title?, default, forced, channels?,
    sampleRate? }` (`default`, `forced` booleans; `channels`, `sampleRate` integers).
  - `subtitleTracks[]`: `{ index, codec, language?, title?, default, forced }`.
  - `chapters[]`: `{ startMs, endMs, title? }`, integers in milliseconds.
- Error codes: `invalid_request` 400, `unauthorized` and `invalid_credentials` and
  `invalid_token` 401, `forbidden` and `unsafe_path` 403, `not_found` 404,
  `payload_too_large` 413, `unsupported_media_type` 415, `invalid_range` 416,
  `probe_failed` 422, `rate_limited` 429, `internal_error` 500.
- Range follows RFC 9110: one range is honoured; an unparseable or multi-range
  header is ignored and the whole file is sent with 200.

## M0 hotkeys (Windows)

Space play/pause; `←`/`→` 5 s; Shift 30 s; Ctrl 90 s; Alt 1 s; `,`/`.` previous/next
frame; `[`/`]` speed −/+ 0.1; `/` normal ↔ previous speed; `F` fullscreen; `Shift+M`
and `Ctrl+M` mute; `Esc` leaves fullscreen, then leaves the player. Mouse clicks on the
video do nothing. Android in M0: tap shows controls with play/pause, a seek bar and
step buttons.

## Done when

- The user has installed both apps from GitHub Releases and both have updated
  themselves at least once without a manual step.
- All six sample kinds play on Windows (HEVC 10-bit with ASS, H.264 High 10, AV1 anime,
  AV1 stream archive, short and long `.ts`), with exact back and forward steps.
- The benchmark has been run on the real phone and the result, with the engine
  decision, is written into ARCHITECTURE.md.
